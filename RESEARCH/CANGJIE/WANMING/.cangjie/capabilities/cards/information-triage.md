# 信息分流与决策优先级

## R — Reading

> “把各部门报来的文件分类，再按紧急和重要程度一一报给刘民有处理。”

出处：第五卷第16章《文登军报》。同章还写明中间层通常附带处理意见。

## I — Interpretation

当世界线增多，最高决策者不能继续直接吸收所有原始信息。
先设一个信息入口，对材料做分类、优先级判断和缺失检查。
紧急不等于重要；如果永远只处理眼前火情，重要但不急的结构问题会不断制造新的紧急事件。
中间层可以提出处理建议，但不能把需要上层裁决的价值判断悄悄做掉。
这样既符合组织运行，也让叙事能通过文书流更新多个子系统，而不把主角写成全知。

## A1 — Application Example

**类型：书中案例。**

输入/问题：民政系统同时收到人力、建设、工厂、学校和组织规划等多类事项。

执行：莫怀文先分类，再按紧急与重要程度汇报，通常附处理意见。刘民有还提醒不能因为紧急事务多，就反复拖延重要的结构调整和学堂建设。

结果：信息入口从“所有事直接找领导”变成可排序的处理链。

来源：第五卷第16章《文登军报》。

## A2 — Future Trigger

适用情境：
- 主角每天收到很多军政、商业、民生或情报消息。
- 作者不知道哪些信息该展开、哪些可一句带过。
- 角色总在“亲自听所有汇报”，显得不可能。
- 用户说“多线剧情怎么汇总”“怎么写领导的信息入口”。

语言信号：信息过载、紧急重要、文书流、汇报优先级、triage、information overload、decision queue。

与相邻能力的初步区分：本能力处理**信息进入决策层之前的分流**；scale-restructure 处理整个组织结构，delegated-execution 处理决策之后由谁执行。

## E — Execution

**输入契约**
- 一组待处理信息，每条至少有来源、内容、时间敏感性、影响范围。
- 当前决策者权限与可委派对象。
未知影响不得凭空判高优先级，应标“需补信息”。

**步骤**
1. 分类：按领域和责任归口。完成标准：每条信息只有一个主责任入口，可有协同项。
2. 评估紧急度与重要度：分别判断，不合并成单一“优先级感觉”。完成标准：给出理由。
3. 决定路径：立即裁决、委派处理、例行记录、补充信息。完成标准：每条都有下一动作。
4. 对需上报项附“建议 + 未知 + 风险”，禁止只丢原始材料。
5. 检查“重要但不急”积压；若反复拖延，建立专门处理窗口。

**输出契约**
- 信息分流表：来源 / 类别 / 紧急度 / 重要度 / 去向 / 建议 / 未知
- 决策者待办清单
- 被委派清单
- 结构性积压提示

完成标准：没有信息因“没人负责”停在系统中，也没有所有事项都被升级到最高层。

## B — Boundary

不要用这张卡替代真实场景；重要信息仍应通过人物、行动和后果展开。
不要把“紧急”自动等于“重要”。
不要让秘书或中间层越权做掉本应由领导承担的价值判断。
如果根本问题是职责不清，应使用 power-contract 或 scale-restructure。
